Deep i18n audit and fix.

Problem:
The platform language selector is set to Spanish, but many UI areas still show English:
- Left sidebar: Company Dashboard, Jobs Management, Post Job, Candidates, Worker Search, Admin View, etc.
- Dashboard buttons: Add Workday.
- Salary modal: Salary Rate Presets, Manage your rate presets, Saved presets, New preset, Work location, Normal rate, Extra rate, Create preset, etc.
- Other dashboard/workday/rate labels may also be hardcoded.

Goal:
When the user selects Spanish, the full platform must show Spanish. When English is selected, English. Same for other configured languages if available.

Required:
1. Search the full frontend for hardcoded English user-facing strings.
2. Prioritize:
   - AppShell / sidebar navigation
   - Dashboard
   - Workday modal
   - Salary rate presets modal
   - Profile page
   - Admin area
   - Job/company/worker modules
3. Replace hardcoded strings with i18next `t()` calls.
4. Add missing keys to:
   - src/i18n/locales/es.json
   - src/i18n/locales/en.json
5. For now, at minimum fully support ES and EN.
6. Keep the current visual layout exactly the same.
7. Do not change business logic.
8. Do not change Dashboard profile completion layout.
9. Add a small fallback only if a key is missing, but do not leave visible English in Spanish mode.
